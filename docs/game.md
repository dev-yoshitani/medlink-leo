# 通信センターの遊び方

複数の依頼を選び、衛星の通信時間を割り振って、利益で通信網を育てる1人用ゲームです。
架空の医療データを使い、1営業日は06:00〜12:00の6時間として計算します。
画面を閉じている間は進みません。

## 起動・再開

Windowsでは、リポジトリ内の **Start-Game.bat** をダブルクリックします。
[通信センター](http://127.0.0.1:8502/) が開きます。開けない場合は同じファイルを再実行します。
初回だけPython 3.11以上と環境の用意が必要です。既に `.venv` がある場合は不要です。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

起動エラーの記録は `outputs/preview/game-launch.log` です。
Windows以外は次のコマンドで起動します。

```sh
streamlit run app/streamlit_app.py --server.address 127.0.0.1 --server.port 8502
```

## 1日の流れ

朝の確認 → 依頼を受ける → 配送計画 → 運用開始 → 報酬受領 → 投資 → 翌日。
初期資金は500 C、信用40、衛星1機、札幌局1か所です。

### 最初の3営業日

画面上部の「運用ガイド」は、完了した操作にチェックを付け、次の操作の画面へ案内します。
「案内を閉じる」で省略でき、「遊び方を開く」で再表示できます。
「前へ」「次へ」で案内を見直し、「今の操作へ」で当日の案内へ戻ります。

1. **1日目**：「依頼手帳」で定期便を受注します。「配送計画」の「自動で計画」で到着予測を確認します。「運用開始」で結果を確定し、「報酬を受け取る」で精算します。
2. **2日目**：急ぎの便と大容量便など、2件を受けます。「案1を保存」の後、通信枠の選択欄と「前へ／後ろへ」で割り当てと順番を変えます。「案2を保存」で、利益と期限内件数を比べます。使う案を選んで運用します。
3. **3日目**：配送の報酬を受け取ります。「衛星・設備」で札幌局を選び、受信アンテナの「強化」を押します。翌日の通信時間表に出る容量を確認します。

本番の資金を使わずに試す場合は「練習場」を開きます。各章3つ、合計12課題があります。
「比較案1を使う」「比較案2を使う」で結果を比べ、自分でも枠と順番を変えられます。
表示される練習得点は本番の報酬ではありません。

## 依頼を選ぶ

毎朝6種類の依頼が届きます。継続中の契約があると、その日の必要分も追加されます。
最初は3件、運用研究で最大6件まで同時に受注できます。
受注前に、荷物の量、生成時刻、期限、達成に必要な期限内件数、報酬、未達費用を確認します。
定期便は信用が下がっても受注できます。継続契約は第3章・運用研究Lv.2、臨時依頼は信用50で開放します。
受注時に自動計画を作るため、配送見込みがその場で変わります。

運用前なら「受注を取り消す」で無料で取り消せます。継続中の契約は当日の決算まで続きます。
運用開始後は計画を変更できません。

## 通信時間を割り振る

「配送計画」には、衛星・地上局ごとの通信時間表と、荷物の一覧があります。
緑は通信できる時間、黄は予定した送信です。

- 「自動で計画」は、期限を優先して通信枠を選びます。
- 各荷物の選択欄で枠を指定します。「未割り当て」では送信しません。
- 「前へ／後ろへ」で、同じ枠を使う荷物の優先順を変えます。
- マウスでは荷物を枠へドラッグし、荷物の行同士のドラッグで順番を変えられます。
- 通信枠を押すと、先頭の未割り当て荷物を割り当てます。
- 「案1を保存」「案2を保存」で2案を保存し、「案1を使う」「案2を使う」で戻せます。

荷物は生成された時刻より前には送れず、1つの通信枠で全量を送り切る必要があります。
同じ衛星は同時に1件だけ送信できます。地上局も、受信設備1台につき同時に1機だけ受けられます。
「枠の最大空き」は、現在の計画後に残る最も大きな連続した空き時間の容量です。生成時刻と期限によっては利用できません。
割り当ての順番は優先順です。後から生成される荷物を先に割り当てても、空いた早い時間を他の荷物が使えます。

到着予測には「期限内に到着」「期限を超過」「容量不足・競合」などの理由が出ます。
期限までの秒数が負なら遅延です。通信枠の合計容量は、競合や生成時刻を考慮する前の値です。
予測と本番は同じ通信計算を使います。

## 報酬を受け取る

「運用開始」で結果を固定すると、すぐに **「報酬を受け取る」** が表示されます。
再生が終わるまで待つ必要はありません。通信センター、配送計画、運用記録から受領できます。

決算は、配送報酬＋達成ボーナス−維持費−未達費用です。精算後は「報酬は受領済み」と表示します。
同じ決算を繰り返し受領したり、再読み込みしても重複精算しません。
再生の一時停止、0.25×／1×／4×／16×、時刻スライダー、「最後まで」は結果を変えません。

受領後は設備に投資するか、「翌日へ進む」で新しい依頼を開きます。

## 通信網を育てる

設備を変更できるのは、受注前と報酬受領後です。中央の地図で施設を選んでも強化できます。
アンテナの大きさ、建物、受信設備の絵は設備の段階に合わせて変わります。

| 投資 | 主な効果 |
|---|---|
| 受信アンテナ | 送れる量を増やす |
| 地上回線 | 受信後、病院への中継点までの時間を短縮する |
| 受信設備 | 同時に受けられる衛星を増やす |
| 地上拠点 | 通信できる場所と時間を増やす |
| 衛星 | 機種と軌道プランを選び、通信機会を増やす |

衛星は最大6機、地上拠点は最大6か所です。小型衛星は800 C／日額20 C、大容量衛星は1,600 C／35 C、高出力衛星は3,000 C／60 Cです。
小型衛星は第2章、全機種は第4章で購入できます。
軌道プランは朝の便・補完の便・広域の便から選びます。購入画面で、選んだ機種の容量と既存の通信時間との重なりを比べます。

研究は受信設備・地上回線・運用の3系統、各3段階です。契約達成でもらうポイントと資金を使います。
追加の衛星と拠点は休止・再開できます。衛星の売却額は購入費の60％です。基本衛星と札幌局は維持します。

## 章の目標と失敗からの復旧

目標達成後に「次の章へ」を押します。自動では進みません。

| 章 | 目標 |
|---|---|
| 1：小さな通信センター | 契約5件達成・設備強化1回 |
| 2：ふたつの衛星 | 衛星2機・地上拠点2か所・期限内到着累計20件 |
| 3：地域をつなぐ | 地上拠点3か所・継続契約1件達成・信用60 |
| 4：広域通信網 | 衛星4機・地上拠点6か所・直近5営業日で対象20件以上かつ期限内到着率90％以上 |

第4章の後も自由に運営できます。日ごとの練習課題、直近30日の記録、累計実績を残します。
契約達成で信用＋1、未達で−1、日次の変化は最大±3です。

維持費を払えない朝は復旧モードに入ります。追加設備を休止し、基本衛星と札幌局の維持費を免除します。
毎日の救済定期便で資金を稼げます。資金100 C以上で通常運営に戻り、追加設備は自分で再開できます。
所有設備や実績は消えません。

依頼の増加、回線の混雑、設備点検、通信条件の悪化は、計画前に知らせます。予測にも反映します。

## セーブの保管・読み込み

対応するChrome／Edgeでは、同じURLのブラウザーに自動保存します。別タブで記録が更新されたら、古い画面の編集を止めます。
その画面の「最新の記録を読み込む」で再開します。

1. 閉じる前に「セーブをファイルに保管」を押すと、JSONファイルをダウンロードできます。
2. ファイルから再開するには、画面下の「セーブファイル・配送の計算結果」を開きます。
3. 「セーブを読み込む」でファイルを選び、「このセーブで再開」を押します。
4. ゲーム内の **「読み込みを確定」** を押します。読み込み完了の表示を確認します。

「前のセーブへ戻す」は直前の自動保存へ戻します。読み込めない記録は保護し、「保護した記録を書き出す」で保管できます。
自動保存が使えない表示が出たら、閉じる前に必ずファイルへ保管します。異なるURL、ポート、ブラウザーでは保存領域が別です。
旧形式の資金・設備・実績は引き継ぎます。旧形式で配送中だった依頼は旧計算で一度精算して移行します。
旧版の操作案内は [game-legacy.md](game-legacy.md) に残しています。

## 計算の範囲

ゲームは架空の円軌道で距離と仰角を計算し、RF計算から通信速度を求めます。
衛星間中継と診療所からの送信は省略し、荷物は選んだ衛星に搭載済みとして扱います。
「経路シミュレーション」は過去の固定TLEによる解析機能です。
ゲームの結果には `source: synthetic-circular-game-v1` を付け、解析結果と識別します。

数値はゲーム用設定です。実衛星や実医療の運用結果を示すものではありません。
設計は [game-update-design.md](game-update-design.md)、検証記録は [game-update-verification.md](game-update-verification.md) を参照してください。
