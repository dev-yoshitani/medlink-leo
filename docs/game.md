# 通信センターの遊び方

衛星で待っている架空の医療データを地上局へ送り、病院側の中継点まで届ける
運用・育成ゲームです。依頼を繰り返して資金を増やし、設備と通信拠点を育てます。

## 起動する

この作業環境では、リポジトリ内の **Start-Game.bat をダブルクリック**します。
ブラウザーで `http://127.0.0.1:8502/` が開き、最初に「通信センター」が表示されます。
ブラウザーを閉じた後も同じファイルから再開できます。PCを再起動した場合は、
このファイルがローカルサーバーを起動します。

### 初めて環境を用意する場合

Python 3.11以上を用意し、リポジトリのフォルダーで次を実行します。
既に `.venv` がある作業環境では不要です。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

その後は Start-Game.bat から起動できます。開けない場合は同じファイルを再実行し、
起動エラーが出たときは `outputs/preview/game-launch.log` を確認します。
別のURLを使うと、そのURLのブラウザー保存領域で始まります。

Windows以外では、環境を用意して次のように起動できます。

```sh
streamlit run app/streamlit_app.py --server.address 127.0.0.1 --server.port 8502
```

## 最初の依頼

1. 「依頼手帳」で **朝の定期便** を受注します。
2. 経路の選び方と送る順番を決め、**配送開始** を押します。
3. 地図の荷物と配送状況を見届けます。**一時停止**、速度ボタン、**最後まで** を使えます。
4. 結果が表示されたら **報酬を受け取って次へ** を押します。
5. 「設備を育てる」で地上局を選び、受信アンテナや地上回線を強化します。

初期資金は150 C。札幌が開いており、ソウル・東京は未開放です。
依頼を受ける費用はなく、未達でも資金は減りません。配送前なら受注を取り下げられます。
配送を始めたら結果を確認して終えてください。受注中は設備を変更できません。

再生1×では、計算上の最後の到着まで約36秒で進みます。0.25×・1×・4×・16×を選べます。
これは計算結果の再生速度です。速度を変えても到着時刻や報酬は変わりません。
OSで動きを減らす設定をしている場合は、一時停止した状態で始まります。

## 設備と地上局

| 設備 | 強化の効果 | 最大レベル |
| --- | --- | --- |
| 受信アンテナ | 1レベル上げるごとに受信利得が2.5 dBi増え、既存のRF計算で通信容量を再計算 | 5 |
| 地上回線 | 1レベル上げるごとに元の遅延を0.6倍にし、病院への到着を早める | 5 |

強化費用は「100 × 現在のレベル² C」です。Lv.1から2は100 C、Lv.2から3は400 C。
受信アンテナが育つとアンテナが大きくなり、Lv.3以上で小型アンテナが加わります。
地上回線が育つと建物と回線の表示が変わります。

| 地上局 | 必要な依頼達成回数 | 開放費用 |
| --- | ---: | ---: |
| 札幌 | 最初から利用可能 | 0 C |
| ソウル | 2回 | 350 C |
| 東京 | 5回 | 650 C |

地上局には通信できる時間と地上回線の遅延の違いがあります。
画面に表示する容量は、計算期間内の通信機会を合計した値です。
既存のモデルでは1件のデータをひとつの通信機会に収める必要があるため、
容量の合計が足りていても配送できない場合があります。
衛星の無線機は1台で、同時に複数の地上局へ送れません。

## 依頼を広げる

| 依頼 | 開放に必要な達成回数 | 期限内到着の目標 | 達成ボーナス |
| --- | ---: | ---: | ---: |
| 朝の定期便 | 0回 | 2/2件 | 100 C |
| 波形をまとめて | 1回 | 3/3件 | 170 C |
| 画像のまとまった便 | 3回 | 2/3件 | 250 C |
| 短い期限の依頼 | 5回 | 3/4件 | 320 C |
| ふたつの通信機会 | 10回 | 5/6件 | 450 C |

到着が1件以上あれば20 C、期限内到着1件につき50 Cを受け取れます。
目標に届けば達成ボーナスが加わり、依頼達成回数が増えます。
同じ依頼を繰り返すと、データ量が最大12%、生成時刻が最大20秒だけ変わります。
変化は依頼番号から決まり、同じセーブと方針なら同じ計算結果になります。
全依頼を開放した後も、依頼と設備強化を続けられます。

## 保存して続きから遊ぶ

進行はこのブラウザーに自動保存します。資金、設備、地上局、達成回数、受注中の依頼、
直近24便の記録が残ります。累計の到着件数と配送回数は記録が24便を超えても残ります。
配送中に閉じても、再開時は同じ計算結果を最初から再生でき、報酬を二重に受け取れません。

- **同じURLで再開:** `127.0.0.1` と `localhost`、ポート8501と8502は別の保存領域です。
- **ファイルで保管:** 画面下の「セーブファイル・配送の計算結果」を開き、
  「セーブを書き出す」でJSONファイルを保管します。
- **別のブラウザーで再開:** 同じ欄でファイルを選び、「このセーブで再開」を押します。
  200 KBまでのバージョン1のセーブに対応しています。不正な形式では現在の進行を置き換えません。
- **読み込みを戻す:** 「前のセーブに戻す」で、最後に変更される前の進行へ戻せます。
  復元前の進行もひとつ前のセーブになるため、戻した操作をやり直せます。

ブラウザーのデータを削除すると自動保存も消えます。大切な進行はファイルにも保管してください。
自動保存が利用できない場合は画面に表示します。その場合もファイルを書き出して続けられます。
アカウント同期やサーバー共通のセーブはありません。

## 計算結果を確認する

ゲームの「配送結果と計算の記録」に、選択した地上局、到着時刻、期限、選択理由が出ます。
配送を始めた後は、画面下の専用欄から計算結果のJSONも書き出せます。
詳しい比較は画面上部の「経路シミュレーション」「通信リンク」を使います。

ゲームは既存の `build_contact_plan` と `route_scenario` を呼びます。
アンテナの利得と地上回線の遅延は入力へ反映し、表示用の到着結果を加減していません。
元の軌道伝播、RF、送信順、経路選択、ベンチマークの計算実装は維持しています。

資金、報酬、開放条件はゲーム用です。データは架空で、優先度は説明用の分類です。
地図は模式図で、固定した過去のTLEを使います。実際の衛星の現在位置ではありません。
診療所から衛星へのアップリンクは省略しており、臨床判断や実際の医療活動には使えません。

## 開発時の確認

```powershell
.venv\Scripts\python.exe -m pytest
.venv\Scripts\ruff.exe check .
.venv\Scripts\python.exe -m mypy
node --test tests/game_ui.test.mjs
node --check app/game/board.js
.venv\Scripts\python.exe scripts/start_game.py --no-browser
```

Node.jsは表示ロジックのテストだけに使います。ゲームの起動にビルド作業やNode.jsは不要です。
ブラウザー確認はローカルで行い、公開デモへの反映は別途必要です。

2026-09-27のローカル確認では、Pythonの127テスト、表示ロジックの5テスト、Ruff、
mypy、JavaScript構文チェックが通りました。ブラウザーで受注・配送・報酬・設備強化・
ソウル開放を操作し、サーバー再起動後の自動復元、セーブファイルの内容と読み込み、
ひとつ前の進行への復元を確認しました。390px幅ではページ全体の横はみ出しがなく、
地図を独立して左右に動かせます。起動用のPythonとPythonwは `--no-browser` で確認しました。
バッチファイルのダブルクリックとOSの既定ブラウザーを開く操作は、この検証では実施していません。
