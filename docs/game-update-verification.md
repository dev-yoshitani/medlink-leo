## 投資に意味があるか

実際の距離・仰角・RF速度を使って、同じ荷物に対する衛星増設、東京局増設、札幌の地上回線強化を比較しました。

- 札幌の最初の通過より早い期限には、東京局の追加が有効。
- 現在の衛星が通信できない時間に生成される荷物には、補完軌道の衛星が有効。
- 東京の通過終了後に生成され、受信後の転送が期限に響く荷物には、地上回線の強化が有効。

この3条件で、それぞれ異なる投資だけが期限内到着を達成します。表示結果を直接変更して差を作っていません。
アンテナ強化はRF容量、高出力衛星は送信電力、大容量衛星は帯域に反映します。

## 修正した不具合

- 継続契約を翌朝保存すると、依頼手帳と継続一覧の同じ荷物を二重に数えて復元を拒否していた。
- 整数と小数のJSON表現が変わると、復旧モードの決算IDが一致しなくなる場合があった。
- 売却後の設備一覧を使って、確定済みの通信枠を誤って無効と判定していた。
- 追加設備の維持費で、復旧直後に再び資金不足になる場合があった。追加設備を休止したまま通常運営へ戻す。
- サーバーのセッションが消失しても、開いたままの画面が復元を再要求しなかった。
- 衛星の購入比較が小型衛星だけの数値になっていた。選択機種と当日の条件で計算する。
- ドラッグの移動先が計画にない場合、先頭へ移動する処理になっていた。移動元・移動先の両方が有効な場合だけ並べ替える。
- ユーザーから「動くが狙った位置に移動しない」と報告があった。行のどこへ落としてもその前へ入れていたため、隣の行の下へ移動できなかった。行の上下で挿入先を分け、位置を示す線とつかみ場所を追加した。
- 通信枠の変更だけでも末尾へ移動していた。現在の送信順を保持するよう修正した。

## これまでの確認の限界

画面の確認はローカルのアプリをエージェントが操作した結果です。ユーザーによる楽しさの評価や、15〜30分のプレイ時間の実測を示しません。
390pxの確認は実アプリを埋め込んだブラウザー内の表示試験で、実機スマートフォンの試験ではありません。
マウスクリックと選択欄・順序ボタンは確認済みです。ドラッグは、この自動操作ブラウザーがページのスクロールとして実行したため、実操作による確認が残っています。HTMLのドラッグ処理とタッチ／ペンの捕捉処理を実装し、並べ替えの計算はテストしています。
2026-10-02の追加確認では、一度エラー画面の読み取りがブラウザーのURLポリシーで拒否されました。後にユーザーが開いた正常なHTTP画面は読み取れました。修正版のつかみ場所・操作案内の表示と、735 Cの記録の再開を確認しています。ドラッグのイベント処理はDOMを模した単体試験で検証しています。自動ブラウザーのドラッグでは並び順の変更を確認できず、修正版の実操作確認は残っています。
Windowsの起動処理は確認しますが、Explorerからの物理的なダブルクリックやPC再起動は自動操作環境では行っていません。
ブラウザーの保存容量不足は模擬試験です。ゲームの数値は初期設定であり、遊びやすさの継続調整が必要です。
