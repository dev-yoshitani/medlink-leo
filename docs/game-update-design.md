# MedLink-LEO 全面アップデート設計書
## 小さな通信センターから、衛星通信網を育てる経営ゲームへ

更新日：2026-10-02。対象はローカルのゲーム版である。

この文書は、ゲーム全体の目標と完成条件を定める。現在の作業版には、複数受注、手動計画、衛星購入、研究、章進行などのコードが既にある。今後の作業は、各機能をこの設計に照らして仕上げ、選択の違いがプレイヤーに伝わる内容へ調整する。実装・確認の記録は [game-update-verification.md](game-update-verification.md) に分けて残す。

## 1. 目指すゲーム体験

**複数の依頼を選び、限られた通信時間を割り振り、利益で衛星と地上拠点を増やしていくゲーム**にする。

旧版は、依頼1件の受注と配送方針の選択が主な操作であった。全面改修では、受注する仕事、荷物の送信順、衛星と地上局の組み合わせ、設備への投資が結果に影響する。

| 項目 | 採用する方針 |
|---|---|
| 進行 | 計画して1日ずつ進める |
| 遊びの中心 | 経営と配送戦略 |
| プレイ時間 | 15〜30分で数日分を進める |
| 成長 | 地上拠点、研究、衛星の購入 |
| 衛星の操作 | 機種と軌道プランを選択 |
| 失敗 | 損失はあるが、立て直せる |
| 長期目標 | 章ごとの目標達成後、無期限で運営 |
| 見た目 | 親しみやすい2D経営ゲーム |

想定プレイヤーは、衛星通信の専門知識がなくても遊べる人である。通常画面では「送れる量」「通信できる時間」「到着までの時間」を使い、技術的な条件は詳細表示にまとめる。

以下の数値は**実装開始時のゲーム用設定値**であり、検証済みのバランスを示すものではない。

### 何を考えると面白くなるか

毎日、次の判断を少なくとも1つ置く。表示される利益だけで決められる日が続く場合は、依頼の組み合わせや通信時刻を調整する。

| 判断 | 選択肢 | 選んだ結果として見せること |
|---|---|---|
| 今日の仕事 | 安定した定期便を増やす／急ぎの便を引き受ける | 利益、期限内件数、未達費用、信用の変化 |
| 限られた通信枠 | 大容量便を先に送る／急ぎの荷物に枠を残す | 届く荷物と遅れる荷物、その理由 |
| 次の投資 | 衛星を増やす／地上局を増やす／回線を強化する | 通信の空白、受信の混雑、転送の遅さのどれを解消するか |
| 数日間の運営 | 継続契約で収入を確保する／翌日の依頼に余力を残す | 翌日も必要になる受注枠と配送能力 |

例えば「急ぎの便を優先して信用を守る案」と「まとめ便を完遂して利益を取る案」を比較できる日にする。これはシナリオの設計例であり、特定の日の計算結果を示すものではない。比較画面では、どちらの案で何を得て何を失うかを同じ場所に表示する。

成功時には、届けた荷物、収益、章目標の進捗を見せる。失敗時には「枠が足りなかった」「地上回線の転送が遅かった」など、次の計画や投資に使える理由を残す。

## 2. 遊び方と追加する機能

### 1日の流れ

**朝の状況確認 → 依頼を選ぶ → 配送計画を組む → 運用開始 → 決算 → 投資 → 翌日**

1日はゲーム内の6時間の運用シフトとして扱う。実時間の待機は不要で、画面を閉じている間は進行しない。1日分の操作は4〜6分を目安とする。

### 依頼を組み合わせる

毎朝6件の依頼を提示し、最初は最大3件、研究で最大6件まで同時に受注できる。

| 依頼の種類 | プレイヤーが考えること |
|---|---|
| 定期便 | 低い報酬でも確実な収入を確保する |
| 急ぎの便 | 期限が近い荷物へ早い通信枠を使う |
| 大容量便 | 大きな荷物を収められる通信機会を確保する |
| まとめ便 | 複数件を届けて達成ボーナスを狙う |
| 継続契約 | 数日間、必要な通信枠を予約する |
| 臨時依頼 | 通常業務に加えて引き受ける余裕があるか判断する |

受注前に、荷物の量、期限、必要な達成件数、報酬、未達時の影響を表示する。選択中の依頼を合算した配送見込みも確認できる。

依頼とイベントは「セーブの種・日数・コンテンツの版」から決定する。再読み込みしても内容は変わらない。

### 通信時間を自分で割り振る

配送計画画面に、**衛星と地上局ごとの通信時間表**を追加する。

- 荷物を通信枠へ割り当て、送信順を変更する。
- 「自動で計画」を使った後、必要な部分だけ修正できる。
- ドラッグ操作に加えて「枠を選ぶ」「前へ／後ろへ」のボタンを用意する。
- 割り当てごとに到着予定、期限までの余裕、残り容量を更新する。
- 衛星や地上局の競合は、その場で理由を表示する。
- 保存できる比較案は2つまでとし、利益と期限内到着件数を比べられる。

例えば、大容量便を先に送ると、後から生成される急ぎの荷物に使える通信時間が減る。急ぎの便を優先すると、大容量便を次の通信機会へ回す必要がある。このような判断を各日の中心に置く。

運用開始後は計画を固定する。再生速度やスキップは結果に影響しない。

### 衛星と地上局を増やす

完成時の上限は**衛星6機、地上拠点6か所**とする。最初は衛星1機と札幌局で開始する。

| 衛星の機種 | 特徴 | 購入費／日額維持費 |
|---|---|---:|
| 小型通信衛星 | 安価で、少量の定期便に向く | 800 C／20 C |
| 大容量通信衛星 | 広い帯域を使えるが維持費が高い | 1,600 C／35 C |
| 高出力通信衛星 | 通信条件が悪い場面に強い | 3,000 C／60 C |

機種の効果は帯域や送信電力などの計算入力へ反映する。

軌道は、通過時刻の異なる固定プリセットから選ぶ。購入画面には、**現在の衛星と通信時間がどれだけ重なるか**を表示する。同じ時間に通る衛星を増やす場合と、通信できない時間を補う場合で効果が変わる。

地上拠点では次を選べるようにする。

- アンテナ強化：受信能力を上げる。
- 地上回線強化：病院への転送を早める。
- 受信設備の増設：同時に受けられる衛星数を増やす。
- 設備の休止：通信能力を減らして維持費を抑える。

衛星は1機につき送信1件、地上局は初期状態で受信1件に制限する。衛星を増やすだけでは、地上局の混雑を解消できない。

### 研究と経営

研究は「受信設備」「地上回線」「運用」の3系統、各3段階とする。研究ポイントは契約達成で得られ、資金とポイントを使って開放する。

研究の成果は、受信設備の増設、回線強化の上限、同時受注数、継続契約の開放へつなげる。配送計画の基本操作と予測表示は最初から使える。

経営では、資金と信用を管理する。

- 新規開始時の資金は500 C、信用は40。
- 日次利益は「配送報酬＋達成ボーナス−設備維持費−契約で明示した未達費用」とする。
- 契約達成で信用＋1、未達で−1。1日の変化は最大±3。
- 信用が下がっても定期便は受注できる。
- 受注前の取り消しは無料。運用開始後は結果に従って精算する。
- 維持費を払えない場合は復旧モードへ移る。追加設備を休止し、基本衛星と札幌局の維持費を免除する。
- 復旧モードでは、基本設備で達成できる救済便を毎日提示する。資金100 C以上で通常運営へ戻れる。

設備や実績は資金不足で消失させない。衛星の売却価格は購入額の60％とする。

イベントは、依頼の増加、回線の混雑、設備点検、通信条件の悪化の4種類から始める。**計画を確定する前に影響を知らせ、予測計算にも反映する。**

## 3. 成長目標と画面設計

### キャンペーン

章は自動で進めず、条件を満たした後に「次の章へ」で移行する。

| 章 | 新しくできること | 達成条件 |
|---|---|---|
| 1：小さな通信センター | 複数依頼と送信順の調整 | 契約5件達成、設備強化1回 |
| 2：ふたつの衛星 | 2機目の購入、通信時間の補完 | 衛星2機、地上局2か所、期限内到着累計20件 |
| 3：地域をつなぐ | 継続契約、受信設備の増設 | 地上局3か所、継続契約1件達成、信用60 |
| 4：広域通信網 | 全機種・全拠点と高難度依頼 | 衛星4機、地上局6か所、直近5営業日の期限内到着率90％以上、合計20件以上配送 |

達成後は無期限運営へ移る。日ごとの課題と累計実績を残し、利益重視、配送量重視、期限厳守などの目標で続けられる。

### 画面構成

| 画面 | 主な内容 |
|---|---|
| 通信センター | 中央の2Dマップ、今日の状況、次の目標、選択中の施設 |
| 依頼手帳 | 依頼の比較、受注、継続契約 |
| 配送計画 | 荷物一覧、通信時間表、競合と到着予測 |
| 衛星・設備 | 購入、軌道プラン比較、強化、休止、売却 |
| 研究 | 開放済みの機能と次の研究 |
| 運用記録 | 日次決算、配送結果、失敗理由、累計実績 |

施設を強化すると、アンテナ、建物、回線の絵が変わる。新しい衛星の購入も中央のマップへ反映する。選択した施設には、性能と次にできる操作をまとめて表示する。

色は紙色、緑、青を基本とし、警告に黄、失敗に赤を使う。色だけに頼らず、アイコンと短い文を添える。専門用語、長い説明、装飾的なカードを通常画面へ詰め込まない。

### チュートリアルと報酬

最初の3営業日を、実際に操作するチュートリアルにする。

1. 定期便を受注し、自動計画、配送、報酬受領まで行う。
2. 期限の異なる2依頼を受け、送信順を変えて結果の違いを見る。
3. 稼いだ資金で設備を強化し、配送可能な量の変化を確認する。

案内はスキップ、再表示ができる。新機能の開放時は、その操作だけを短く説明する。

決算画面には報酬の内訳と**「報酬を受け取る」**を常時表示する。アニメーションの終了を受領条件にしない。受領済みの決算は明示し、連打や再読み込みで重複精算しない。

## 4. 実装構成とセーブ互換性

### ゲーム計算

現在のStreamlitとブラウザー内の2D画面を土台に、経営状態、コンテンツ、通信計画、画面表示を分離する。

複数衛星向けに、次のゲーム用インターフェースを新設する。

| 型・操作 | 役割 |
|---|---|
| `CampaignState` | 日数、資金、信用、設備、衛星、研究、契約、決算 |
| `DailyPlan` | 荷物、衛星、通信枠、送信順の割り当て |
| `preview_day(state, plan)` | 状態を変更せず、配送結果と決算見込みを返す |
| `commit_day(state, plan)` | 当日の条件と計画を固定し、決算を作成する |
| `claim_day(state, settlement_id)` | 指定決算を一度だけ精算する |

衛星ごとに送信占有時間、地上局ごとに受信占有時間を管理する。1件の荷物は1つの通信機会で送り切る方式を採用する。予測と本番は同じ計算を呼ぶ。

ゲームの軌道プリセットには、架空の円軌道を扱う簡略モデルを新設する。地上局からの距離と仰角を計算し、既存のRF計算と転送容量の計算へ接続する。衛星間中継と診療所からのアップリンクは今回の対象外とし、荷物は割り当てた衛星に搭載済みとして扱う。

既存の経路シミュレーションは、過去の固定TLEを使う解析機能として維持する。ゲーム用モデルと解析用モデルは、結果の書き出しでも識別できるようにする。

### 保存と復元

- セーブ形式を`save_version: 2`へ更新する。ブラウザーの保存キーの版とは区別する。
- 計画、未受領の決算、精算済みID、日次の種、コンテンツの版を保存する。
- 操作にIDと期待する状態の版を付け、古い操作と重複操作を拒否する。
- 対応するChrome／Edgeでは保存をWeb Locksで直列化し、他タブの更新を検知した画面は再読込まで編集を止める。
- 保存できない場合は明示し、セーブファイルを書き出せる状態を保つ。
- 旧セーブの資金、設備、累計実績を引き継ぎ、移行前のデータをバックアップする。
- 旧形式の配送中データは従来の計算で精算してから移行し、報酬を重複付与しない。
- コンテンツ更新後も、確定済みの日は保存した条件で再現する。

初版はローカルの1人用ゲームとして完成させる。起動は引き続きWindowsのダブルクリック方式とする。

## 5. 実装順と完成の判定

### 優先順位

| 優先度 | 仕上げる項目 | プレイヤーにとっての目的 |
|---|---|---|
| 最優先 | 起動・再開、報酬受領、保存、翌日への移行 | 途中で遊べなくなる状態を解消する |
| 次 | 複数依頼、手動計画、比較2案、失敗理由、最初の3日の案内 | 計画を変える意味を理解して遊べるようにする |
| 続いて | 複数衛星、地上局、研究、継続契約、復旧 | 稼いだ資金の使い道と長期的な判断を増やす |
| 全体を通して仕上げる | 4章、各章の固定課題、2D画面、難易度調整 | 成長を実感し、異なる方針でも続けられるようにする |

コードがある項目も、操作できることと遊びとして機能することを別々に確認する。追加機能は、受注から受領までの基本操作が通る段階で順に開放する。

全面改修を次の順で進め、各段階で遊べる状態を確認する。

| 段階 | 実装内容 | 次へ進む条件 |
|---|---|---|
| 1 | 日次進行、複数受注、決算、保存移行 | 受注から翌日まで中断・再開できる |
| 2 | 通信時間表、手動割り当て、自動計画、比較 | 選択によって配送結果が変わる |
| 3 | 複数衛星、軌道プラン、地上局競合 | 増設と時間の補完が異なる効果を持つ |
| 4 | 維持費、信用、研究、継続契約、イベント | 失敗から復帰でき、投資先を選ぶ意味がある |
| 5 | 全4章、2D画面、チュートリアル、内容調整 | 新規開始から最終章達成まで通して遊べる |

### 必須の検証

- 同じ状態と計画では、予測と本番の配送結果・報酬が一致する。
- 同じ衛星の送信、同じ受信設備の利用が重ならない。
- 生成前の送信、容量不足、期限超過を正しく判定する。
- 報酬の連打、再読み込み、複数タブ、移行再実行で資金が増減しない。
- どの章でも、資金不足から基本設備と救済便で復帰できる。
- 旧セーブの待機中・配送中・未受領状態を移行できる。
- マウス、キーボード、狭い画面で計画と報酬受領を操作できる。
- 既存の解析機能と計算テストが引き続き通る。

### ゲームとしての合格条件

**同じ設備・同じ依頼でも、少なくとも2つの妥当な計画があり、利益や期限内到着件数に違いが出ること。**

加えて、衛星の購入、地上局の増設、回線の強化のいずれか1つが常に最善にならない内容を用意する。各章に、選択の結果を説明できる固定シナリオを最低3つ設ける。

自動テストに加え、最初の15分、資金不足からの復旧、2機目の購入後、最終章を実際に操作して確認する。ゲーム用設定値の調整はコンテンツ設定へ集約し、計算結果の表示を直接書き換えて難易度を合わせない。
